# Commands: write support for Scry

## Context

Scry is read-only by design: generated client query models, captured LINQ, a restricted wire AST, and a server that re-validates everything against a default-deny allow-list. Several docs state the position outright ("Scry is read-only, so commands, writes … stay ordinary endpoints", `docs/comparisons.md:158`; `docs/linq-coverage.md:208`; `docs/attachments.md:194`).

This round adds writes as **commands**, in the service-bus sense: a command is a message class the client sends, the server validates, authorizes and dispatches, and the outcome comes back **disconnected from the HTTP response** over a push channel. The UI keeps behaving synchronously when the server is idle, and otherwise hands the work to a pending-work panel; it can also see work other users are doing to the rows on screen. A command may be handled in-process or routed through NServiceBus, MassTransit, Rebus or Wolverine, and an existing bus message class can be exposed to the client by annotating it.

Decisions taken with the user:
- Push channel: **Server-Sent Events**, in-box in .NET 10 (`TypedResults.ServerSentEvents` server side, `System.Net.ServerSentEvents.SseParser` client side; `System.Net.ServerSentEvents.dll` ships in `Microsoft.NETCore.App` 10.0.11 and in the browser-wasm runtime pack, verified locally). No SignalR.
- "Can the user run X?": a **type-level bool** on the generated facade (`Query.Commands.CanDeleteEmployee`, from a capabilities endpoint) **plus a per-row bool** on the target's query model (`EmployeeQueryModel.CanDeleteEmployee`), computed server-side in SQL from the command's policy.
- Bus adapters in this round: **NServiceBus 10.2.9, MassTransit 8.5.10 (last Apache-2.0 line; 9.x is commercial), Rebus 8.9.3, WolverineFx 6.33.0**. All target net10.0 (nuspecs checked).

Governing constraint, unchanged: the client is hostile. Every command is re-validated and re-authorized server-side; nothing about hidden rows leaks; the standard is the closed security review in `src/todo.md` (RequireJson, bounded messages, `EnsureDefined` on wire enums, non-null array elements, wire names only in rejections, startup resolvability).

## The design in one page

### Authoring (server model or a messages assembly)

```cs
[Command(typeof(Employee))]                       // targeted: acts on one Employee row
public class DeleteEmployee { public int Id { get; set; } }

[Command(typeof(Employee))]
public class RenameEmployee { public int Id { get; set; } public string Name { get; set; } = ""; }

[Command(Result = typeof(EmployeeCreated))]       // untargeted, with a typed result
public class CreateEmployee { public string Name { get; set; } = ""; public int DepartmentId { get; set; } public Status Status { get; set; } }
public class EmployeeCreated { public int Id { get; set; } }
```

- `[Command]` (`Scry.Annotations`, `AttributeTargets.Class`): ctor `()` / `(Type target)`; `Name` override (blank = unset); `Result` type; `Policy` type (server-only, like `[ReturnableWith]`; the generator ignores it).
- `[CommandIgnore]` hides a payload property (server fills it). `[QueryIgnore]` on a command property is a generator diagnostic and a server startup error.
- Payload = public get+set instance properties, scalar/enum/`byte[]`/nullable of those (plus lists and nested plain DTOs of the same, declared in a command assembly). Navigation, collection-of-entity, entity, `object`, `JsonElement`, dictionaries → refused.
- **Target key binding**: a targeted command carries the target's key as a property named like the key member (`Id`) or `{TargetClrName}{Key}` (`EmployeeId`), derived identically by `MetadataModelReader.Keys` and `Schema.DeriveKeys`; unbound → SCRY010 + startup exception. Consequently `Keys` are populated (and `~keys` stamped, `[ScryModel(Keys=…)]` emitted) for any type that is a command target, extending today's attachment-only gate.
- Commands may live in the model assembly (scanned by default) or in extra assemblies: MSBuild `ScryCommandDll` (`;`-separated) for the generator, `options.AddCommands(Assembly)` on the server.
- Handlers: `ICommandHandler<T>` / `ICommandHandler<T,TResult>` registered in plain DI (`services.AddScoped<ICommandHandler<DeleteEmployee>, DeleteEmployeeHandler>()`), or a bus adapter that claims the command. Startup refuses a command with no route or with two routes (default-deny).
- Policies: `ICommandPolicy<TCommand>.Allow(ScryPolicyContext)` (type-level) and `ICommandPolicy<TCommand,TEntity>.Rows(ScryPolicyContext) : Expression<Func<TEntity,bool>>` (row-level); registered via `[Command(Policy=…)]` or `options.AddCommandPolicy<TCommand,TPolicy>()` (options win). No policy → allowed. A targeted command's row must additionally be visible through the source's `IReturnablePolicy` chain.

### Generated client surface (`Scry.Generated`, `ScryCommands.g.cs`)

```cs
[global::Scry.ScryCommand("DeleteEmployee", Target = "Employee", Keys = new[] {"Id"})]
public sealed class DeleteEmployee { public int Id { get; init; } }
[global::Scry.ScryCommand("CreateEmployee", Result = typeof(global::Scry.Generated.EmployeeCreated))]
public sealed class CreateEmployee { … }
public sealed class EmployeeCreated { public int Id { get; init; } }

public sealed class ScryCommands
{
    public ScryCommands(global::Scry.ScryClient client) => this.client = client;
    public global::System.Threading.Tasks.Task<global::Scry.ScryCommandOutcome> DeleteEmployee(
        global::Scry.Generated.DeleteEmployee command,
        global::System.Threading.CancellationToken cancel = default) =>
        client.SendCommandAsync(command, cancel);
    /// Whether this caller may send 'DeleteEmployee' at all.
    public bool CanDeleteEmployee => client.Can("DeleteEmployee");
    public global::System.Threading.Tasks.Task<global::Scry.ScryCommandOutcome<global::Scry.Generated.EmployeeCreated>> CreateEmployee(…) =>
        client.SendCommandAsync<global::Scry.Generated.CreateEmployee, global::Scry.Generated.EmployeeCreated>(command, cancel);
    …
}
// ScryQuery gains: public ScryCommands Commands { get; }  (only when the model has commands)
// EmployeeQueryModel gains: public bool CanDeleteEmployee { get; init; }  public bool CanRenameEmployee { get; init; }
//   — listed in [ScryModel(...)] members and the default projection; stamped as ordinary (name, "bool") members.
```

Rules: commands ordered by name; types fully qualified (the method/type homonym `DeleteEmployee(DeleteEmployee)`); `CancellationToken` spelled in full; Task-returning plain instance methods (F#-safe). Nothing command-related is emitted when the model has no commands.

### Wire (`Scry.Wire`, camelCase, all roots in `WireJsonContext`, requests in `ScryJson.IsRequest`)

```cs
public sealed record CommandRequest(int Version, string Command, Guid Id, JsonElement Payload) { const int CurrentVersion = 1; string? Stamp; static Create(...) }
public enum CommandStatus { Pending, Completed, Failed }
public sealed record CommandReceipt(int Version, Guid Id, CommandStatus Status) { JsonElement? Result; string? Error; string? Stamp }   // optional members as init props: the writer omits nulls and RequireWhatTheWriterAlwaysWrites would require positional ones
public sealed record CommandCapabilities(int Version, IReadOnlyList<string> Commands) { string? Stamp }
public sealed record WatchRequest(int Version, string Source, IReadOnlyList<IReadOnlyList<AttachmentKey>> Rows) { string? Stamp }   // AttachmentKey(Value, Tag) reused; key order = ordinal by member name, as attachments
[JsonPolymorphic("$type")] [JsonDerivedType(typeof(CommandCompletedEvent), "completed")] [JsonDerivedType(typeof(CommandActivityEvent), "activity")]
public abstract record CommandEvent;
public sealed record CommandCompletedEvent(Guid Id, CommandStatus Status, DateTimeOffset At) : CommandEvent { JsonElement? Result; string? Error }
public enum ActivityPhase { Started, Completed, Failed }
public sealed record CommandActivityEvent(string Source, IReadOnlyList<AttachmentKey> Keys, string Command, Guid CommandId, ActivityPhase Phase, DateTimeOffset At) : CommandEvent { string? Actor }
```

- `WireFormat.ClientHeader = "Scry-Client"`: the client-minted `Guid` every command endpoint reads. It is a **delivery capability** (receipts and `completed` events go only to the client that presents it), so it travels as a header, never in a URL.
- `ScryIntrospection.CurrentVersion = 2`, gains `IReadOnlyList<ScryCommandInfo> Commands` (`Name`, `Target` model name, `Keys`, `Properties` as `ScryMemberInfo`s, `Result: ScryResultInfo?`, `Obsolete`); `ScryMemberInfo` gains `IsCapability` + `Command` (both omitted when default).
- `ScryPermissionException.CommandDeniedMessage = "The command was denied by a server policy."`.
- `NonNullElementsConverterFactory`: cover `IReadOnlyList<AttachmentKey>` (a null row in `WatchRequest.Rows` fails).
- Schema stamp: `src/Shared/SchemaStamp.cs` header `scry-schema-v3`; `Compute` gains `commands` (`command {Name}[ : {TargetModel}]` + members + synthetic `~keys`/`~result`) and `results` sections. Both `StampMembers` mirrors unchanged (capabilities flow as ordinary members); new `StampCommandMembers` pair kept byte-identical.

### HTTP surface (all inside `MapScry(pattern)`'s `Endpoints` aggregate, so `.RequireAuthorization()` covers them)

| Route | Method | Body → answer |
| --- | --- | --- |
| `{p}/command` | POST | `CommandRequest` → `CommandReceipt`: 200 Completed/Failed decided inline within `CommandSyncWindow`, 202 Pending |
| `{p}/command/{id:guid}` | GET | receipt, only for the `Scry-Client` that sent it; else 404 |
| `{p}/capabilities` | GET | `CommandCapabilities` (type-level policy per command for this caller), `no-store` |
| `{p}/watch` | POST | `WatchRequest` → 204; replaces this client's watch set for that source; keys filtered through the source's policy chain first |
| `{p}/events` | GET | `text/event-stream`, `event: command` items with `id: <sequence>`, `Last-Event-ID` replay from a bounded ring, `event: ping` heartbeat every `EventHeartbeat`, `Cache-Control: no-store`, `X-Accel-Buffering: no` |

Failure table for `POST /command` (all `ScryError` bodies, `no-store`): 415 non-JSON; 413 body over `MaxCommandBytes` (checked before reading); 400 wire/version/unknown command/payload (unmapped member, `$type`, wrong type, missing required or key, null element, unknown enum name, depth, DataAnnotations, duplicate id) with messages naming only wire names and the stale suffix when drifted; 403 fixed message for a type-level denial; **404 `"The command's target was not found."` for absent, hidden and row-denied alike** (one query, one answer, as attachments do); 503 `MaxPendingCommands` reached (`Retry-After: 1`); 500 fixed `"Command dispatch failed."`.

### Runtime flow

1. Bind the payload into the **server's** command type through a per-command restricted `JsonTypeInfo` (allow-listed properties only, `UnmappedMemberHandling.Disallow`, `PolymorphismOptions = null`, enums by name only, `MaxDepth = 16`, `RespectNullableAnnotations`), then `Validator.TryValidateObject`.
2. Type-level policy → 403. Targeted: `ResolveSource(target)` (policy chain, cached policies refreshed) + key predicate (`Parameterization.Parameterize`, lifted from `QueryExecutor.PlanAttachment` into a shared `KeyPredicate` helper) + row policy expression → `Any()`; false → 404.
3. `tracker.Accept(record)` (raises `Started` activity) **before** `dispatcher.Dispatch(envelope)`.
4. Await `tracker.Completion(id)` up to `CommandSyncWindow` (request abort only stops the wait); answer inline or `Pending`.
5. In-process dispatcher runs the handler on a background task with its own DI scope and `DbContext`, calls `SaveChangesAsync` when `context.SaveChanges` (default true) and the tracker has changes, serializes a typed result with `ScryJson.Options`, then `Complete`/`Fail`. `ScryCommandException` carries a client-visible message; anything else fails with fixed `"Command execution failed."` and the real message in the audit trail.
6. Tracker fans out: `completed` → origin client; `activity Started/Completed/Failed` → watchers of `(source, key)` ∪ origin.
7. Client: mints `Id`, registers a channel waiter **before** the POST, POSTs with `Scry-Client`, and if `Pending` waits on the channel (or polls the receipt when the channel is not connected) until `CommandWait` (default 3 s from send); past that the outcome is `Pending` with a `ScryPendingCommand` in `ScryPendingWorkStore`, whose `Completion` resolves when the event lands.

### Capability member (`MemberKind.Capability`)

For each targeted command X on E, `E`'s `TypeMeta` (and opted-in subclasses) gets `Member.Capability("X")`: `Name = "CanX"`, `Type = bool`, `Property = null`. Rebinding in `ExpressionBuilder.BuildMemberAccess` and the two default-projection loops: type-level policy denies → `Expression.Constant(false)`; row policy registered → its lambda body with the parameter replaced by the owner expression and every scalar `ConstantExpression` parameterized; else `true`. Computed once per call (`CapabilityContext` created in `QueryExecutor.Walk`, memoized per command). Valid in `Where`, `Select`, nested navigation paths, `OrderBy`, `GroupBy`, `Distinct`, subqueries; not traversable. `NavigationPolicyProbe` and `PlanAttachment` pass no context (reads as `false`, nothing runs). Every `Member.Property` dereference (26 sites, 7 files) gates on kind or null.

## Cross-cutting rules

- Conventions: internal types in the global namespace with no `namespace` line; public in `namespace Scry`; lambda parameters `_`; comments on their own line above code; `Cancel` alias; expression-bodied members; no `PackageReference` versions (CPM; `PackageVersion` in the tree's `Directory.Packages.props`); `TreatWarningsAsErrors` + `EnforceCodeStyleInBuild` in `src`.
- Lockstep readers: `MetadataModelReader` / `Schema` / `ModelSynthesizer` and the two `StampMembers` (+ new `StampCommandMembers`) mirrors change together; `LockstepTests` is the guard.
- Non-disclosure: absent, hidden and row-denied targets answer one 404 after one query; watch registration filters through the policy chain and answers 204 regardless; receipts and `completed` events reach only the `Scry-Client` that sent the command; activity events reach only watchers whose watch survived the policy filter (plus the origin); error messages name wire names only and are bounded.
- Build discipline: never build/test two trees concurrently; never `dotnet publish` a single-TFM `src` project; recovery for the usings storm is `dotnet build src/Scry.slnx`; `dotnet restore src/Scry.slnx` after any stray publish. Stop any running `Sample.Server` before building samples.
- Snapshots: inspect every `*.received.*` against its `*.verified.*` before moving it; the lists above say which moves are expected.

## Flags carried into implementation

- `SignatureDecoder.IsSystemType` returning false is a real prerequisite bug for `typeof(...)` decoding; fix first.
- `;` inside `build_property.ScryCommandDll` through the generated editorconfig is unverified; the generator splits on `;` and `|`, switch the MSBuild join to `|` if the value is truncated.
- `ServerSentEventsResult`'s own `Cache-Control` is unconfirmed; the handler sets `no-store` itself and a test asserts it.
- `HttpClient.Timeout` does not govern reading a streamed body after headers (same assumption as `ToAsyncEnumerable`); check once with a >100 s idle channel.
- Bus APIs are from memory; MassTransit in-memory transport sharing across two bus instances, replying from a Rebus `IIncomingStep`, Wolverine `DeliveryOptions.Headers` and middleware signatures need confirming. Wolverine's `JasperFx` chain under the pinned Roslyn 5.3.0 is the likeliest restore surprise, hence last.
- Composite-key watches use chunked OR-of-ANDs; confirm EF's translation is acceptable at `MaxWatchedRows`.
- A `Can*` row member joins every whole-model query's default projection, so a row policy that is expensive in SQL costs every such query; documented, and explicit `Select`s avoid it.
- Out of scope this round, called out in the docs: a multi-node tracker backplane (the `ICommandTracker` interface allows one), cached (`ICachedRowPolicy`-style) command policies, running commands from the explorer, auto-refetch of arbitrary queries (pages refetch on `ActivityChanged`/`Completion`).
